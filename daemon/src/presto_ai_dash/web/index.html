Set up a Presto Applies to one device

Install the dashboard on a Presto plugged into a computer by USB. You need no copy of this project: this page gives you the exact app this daemon serves, plus a one-time encrypted setup file with the daemon address and device token. Do this once for each Presto. The setup script asks for Wi-Fi locally, so a Wi-Fi password is never typed into this page.

This daemon has no Presto app files to install. Use a release wheel or the container image; a source-only install without the presto/ folder cannot prepare a download.

This daemon generated a new device token at startup, so the Presto will lose access when the daemon restarts. Set daemon.shared_token in the configuration first, then prepare a new download.

Use the daemon computer's LAN address, not localhost and not a container's internal address.

Setup unlock code

Type this code into the setup script on the USB computer. It is not inside either download, and it is shown only once. If it is lost, prepare a new download; the device token is not changed either way.

  1. Download presto_setup.py and presto-setup.enc.
  2. Put both files in one folder on the computer the Presto is plugged into.
  3. Run python presto_setup.py there and type the code when asked. The script installs the app, keeps or replaces the device's own settings, and deletes the encrypted file when setup succeeds.

Demo mode Applies to all services

The DASH_DEMO environment variable controls demo mode for this daemon; edit the environment instead of this page.

While demo mode is on, the Presto and the status API show a scripted set of sample accounts instead of the real ones, with their own demo chip. The real accounts are untouched: no provider is contacted, no reading is stored, and a bell tap on a sample account is remembered in memory only. Turning it off brings the real readings back on the next poll, with no restart.

Alerts are off for all services

Alerts are off for all services: no service chirps, lights up or scrolls Home to an alarm. Turn the master switch on to use the settings below.

A service that has used this much of an allowance turns yellow.

A service that has used this much turns red. It must be above the warning percent. At 100% a service is rate limited, as it always was.

Sound is off until you turn it on here: a desk device must not beep unannounced. Tick this box to let the Presto chirp. One chirp for a warning, two for a critical or rate-limited service. A warning that persists does not chirp again, and a recovery is silent. Long-pressing the Presto mutes the sound for a few hours; the screen shows how long is left.

How long the Presto stays muted after a long press, from 0 to 48 hours. Zero means it stays muted until you long-press again. The screen shows a MUTED chip with the time left, so a mute cannot be forgotten. A restart clears the mute.

In quiet hours the Presto stays silent and its light is dimmed. The times are this computer's local time; the daemon decides when it is quiet, so the device needs no clock.

Home scrolls to a service that has just got worse, once the alarm has held for half a minute. It never moves while you are touching the screen, and it brings your own position back a minute later.

Browser sessions Applies to every browser

A browser stays signed in for seven days. If someone else may have signed in with your admin token, sign every browser out, then lock this page and sign in again. A token you set in the configuration file also ends the sessions made under the old one when you change it; a token the daemon generates at each start does not, so this is the way to end those.

About and help Applies to all services

Cloud and subscription sources

Available subscription connectors show current allowance meters in your source list. OpenCode Go reports quota percentages. Ollama Cloud reports dated activity; monthly included and purchased credits are read separately from rolling activity. Order

The order of the accounts on the Services tab is the order of the Presto Home list and of the swipe cards. It saves automatically and applies on the next poll.

Logs and diagnostics

The daemon writes its own log to the console it was started from (python -m presto_ai_dash.app --config dash.toml --admin). The Problems list on the Status tab shows the recent warnings and errors without reading the log file. The device prints its fetch diagnostics to the Presto's serial console.
